# Обучающий датасет: сбор, разметка признаков, объединение

Этот документ описывает сбор и разметку обучающих данных. Модель, используемая сервисом, обучена
на `ml/datasets/model_compare/gpt-5.6-luna/training.csv` (1327 строк); её метрики приведены в
[отчёте сервиса](09-report.md) и [отчёте о метриках](12-final-metrics.md).

Итоговый файл — `ml/datasets/training_merged.csv`. Валидация — `ml/datasets/gold_features.csv`
(100 записей заказчика, в обучение не входят). Воспроизведение — `ml/datasets/README.md`.

## 1. Наша часть: 400 позитивов и 395 негативов

Аннотаторов у команды нет, поэтому метку ставит не модель «по ощущению», а правило заказчика
(`стадия ≤ 4 и тренд ≥ 2`, восстановлено по колонке «Балл», совпадение 99/100). Модель
только **извлекает** факты из статей и ссылается на их номера. Ссылки берутся из поиска
(Tavily, RSS), а не из ответа модели.

| Шаг | Скрипт | Что делает |
|---|---|---|
| Позитивы | `collect.py`, `rss_source.py` | Tavily + RSS отраслевых изданий за 18 мес → извлечение технологий со ссылками на статьи |
| Вето зрелости | `evidence_sources.py`, `stage_judge.py` | Научные базы и Википедия; стадию 5 определяет судья по тексту статей |
| Трудные негативы | `contrastive_negatives.py` | Для каждого позитива — зрелый «родитель» той же задачи, стадия 5 подтверждена по Википедии |
| Лёгкие негативы | `wiki_negatives.py` | Зрелые технологии из категорий Википедии |
| Дубли | `dedupe.py` | Строки с общими статьями → LLM разбивает на группы; одна статья Википедии = один негатив |
| Отбор | `finalize_dataset.py` | Квоты по областям; негативы зеркалят позитивы по области, чтобы область не выдавала метку |

`collect.py` строит запросы по приоритетному набору из 14 языков. Для Tavily языки детерминированно
распределяются между поисковыми углами внутри области: русский и английский всегда, ещё четыре
локали выбираются циклически; вместе шесть областей покрывают весь набор. Текущие CSV и модель
не обновятся сами: чтобы обучать на новом международном сборе, нужно отдельно запустить майнинг,
собрать признаки и переобучить модель.

В живом поиске (`app/radar/open_sources.py`) запрос расширяется до 14 приоритетных языков и языка
пользователя, если он определён. Локальные варианты идут в региональный Bing News и Crossref;
параллельно GDELT Global News ищет английскую формулировку по своему машинно-переведённому
многоязычному корпусу. Возвращённые GDELT URL загружаются с исходных сайтов, а не оцениваются
по одному заголовку. У GDELT доступно только скользящее окно около трёх месяцев; для более старой
даты оценки этот канал пропускается. Поэтому покрытие шире, но оно не означает буквальный поиск
на каждом существующем языке или доступ ко всем локальным источникам.

Проверка судьи стадии на 50 золотых записях: точное совпадение стадии 43%, ±1 — 76%, ни одна
из 49 записей не названа зрелой. 13 из 14 заведомо зрелых технологий узнаны. Поэтому судья
используется только как вето на стадию 5, а тренд (kappa 0,20) в метку не входит.

| Область | Позитивы | Негативы |
|---|---:|---:|
| Edge | 65 | 65 |
| Защита ИИ | 58 | 53 |
| Индустриальный ИИ | 39 | 39 |
| Инфраструктура ИИ | 39 | 39 |
| Роботы | 100 | 100 |
| Финтех | 99 | 99 |

Пересечения с золотом и с выборкой Арсения исключены ещё при сборе (по названиям и по
английским терминам, `ml/datasets/exclusions/`).

## 2. Разметка признаков: `app/ml/features/extract.py`

Один модуль размечает и обучающую выборку, и кандидатов в сервисе. Выход — 63 признака схемы
`weak-signals-63-v2` (`app/ml/features/schema.py`), та же, что у `scripts/train_logreg.py`.

```python
from app.ml.features.extract import featurize
featurize("Нейроморфные чипы для edge-устройств", "Edge", snapshot=date(2026, 9, 22))
```

1. **Поисковый термин.** LLM переводит название в канонический английский термин и до двух
   синонимов. Термин выводится из названия заново для **всех** строк: термин из этапа сбора
   не используется, иначе источник строки (Википедия у негативов, новости у позитивов)
   просочился бы в признаки.
2. **Свидетельства** (бесплатные источники, окна от даты среза):

   | Канал | Источник | Окна |
   |---|---|---|
| Наука | Crossref и OpenAlex, дедупликация по DOI/заголовку; OpenAlex добавляет аффилиации и страны | 0–2, 2–4, 4–6 лет, старше 6; 3 года; первая работа |
| Патенты | FreePatentsOnline (`FEATURE_PATENTS=1`) | Счётчики и документы по датам подачи; если источник недоступен, признаки остаются пропущенными |
   | Медиа | Google News RSS, `after:`/`before:` | 0–6, 6–12, 12–24, 24–48 мес |

В майнинге и живом радаре используются одинаковые адаптеры OpenAlex, официальных грантовых
реестров, GitHub/Hugging Face, TED и (для медицинских запросов) ClinicalTrials.gov/openFDA.
Все возвращённые документы проходят общую загрузку и проверку источников; отсутствие результатов
не превращается в отрицательную метку.

3. **События.** LLM читает пронумерованные заголовки (до 30 на окно) и выписывает события:
   пилот, внедрение, продукт, раунд, грант, стандарт, регулирование, закупка. Каждое событие
   ссылается на номер заголовка; **дата берётся из заголовка**, события без валидной ссылки
   отбрасываются. По той же ленте модель ставит стадию 1–5.
4. **Формулы** — чистая функция `compute()` без сети: логарифмы счётчиков, рост как разность
   `log1p`, ускорение, HHI, доли. Реестр источников (пресс-релизы, высокое доверие,
   непроверяемые) — в начале `extract.py`.

**Детерминизм.** `temperature=0`, `seed=7`; каждый сетевой и LLM-ответ кэшируется по хэшу
запроса (`ml/.cache/features`, для сервиса — `FEATURE_CACHE_DIR`). Повторная разметка на тот же
срез даёт те же значения; `compute()` покрыт тестом `tests/test_features_extract.py`.
Датасет размечен `google/gemini-3.8-flash`; модель сервиса обучена на разметке `openai/gpt-5.6-luna` тех же строк (`FEATURE_MODEL`, по умолчанию luna) — сравнение LLM в [10-model-comparison.md](10-model-comparison.md).

**Пропуски.** Если источник не ответил, признаки канала остаются пустыми, а не нулём.
`missing_*` = 1, если в канале нет ни одного свидетельства (или он недоступен). Порядок строк
при разметке перемешан по хэшу id, поэтому отказ источника посреди прогона не совпадает
с классом строк.

Semantic Scholar точнее (фразовый поиск), но без ключа в пиковые часы отвечал 429 на
почти все запросы — несколько ответов в минуту. Crossref отвечает стабильно; счёт в окне
ограничен сверху 1000, поэтому объём науки у зрелых областей упирается в потолок.

**Не измеряются** (пусто у всех строк, отсеиваются как константы):
- аффилиации — `institution_count_log_3y`, `industry_affiliation_share_3y`,
  `science_country_count_log_3y`: нужен OpenAlex, а его бесплатный дневной бюджет на IP исчерпан;
- **весь патентный блок в сохранённом `training_merged.csv` и текущей модели** (`patent_*`,
  `patent_to_paper_ratio`, `patent_minus_paper_growth`; `missing_patents` = 1 у всех исходных
  строк). Текущий extractor получает патентные данные только из FreePatentsOnline. Если FPO
  недоступен, патентные поля остаются пропущенными, а не нулями. Интеграцию Google Patents
  BigQuery удалили: публичный набор содержит данные только по 2018 год включительно и не подходит
  для мониторинга свежих сигналов. Сохранённый датасет и модель автоматически не меняются; для
  получения новых патентных признаков надо успешно собрать их из FPO, пересчитать метрики и
  отдельно переобучить модель.

## 3. Объединение с выборкой Арсения: `ml/scripts/build_training_set.py`

1. Обе выборки приводятся к общей схеме, признаки пересчитываются **одним модулем для всех
   строк** — старые признаки Арсения (21 измеримый из 63, у 300 доп. негативов — ни одного)
   не используются, иначе пропуски выдавали бы происхождение и класс строки.
2. Дедупликация по нормализованному термину (и по совпадению термина с синонимом другой
   строки): одна технология — одна строка. Группы с противоречащими метками удаляются.
   Строки с термином из золота удаляются из обучения.
3. `paper_volume_percentile_domain` — перцентиль внутри области по обучающей выборке;
   опорное распределение сохранено в `app/ml/features/paper_volume_reference.json` для сервиса.

### Итог объединения (срез 2026-09-22)

| | Позитивы | Негативы | Всего |
|---|---:|---:|---:|
| Наши | 342 | 365 | 707 |
| Арсения | 56 | 594 | 650 |
| **Итого** `training_merged.csv` | **398** | **959** | **1357** |

Удалено 538 строк (`merge_removed.csv`):

| Причина | Наши | Арсения |
|---|---:|---:|
| Дубль технологии | 47 | 364 |
| Термин совпадает с золотом | 6 | 79 |
| Противоречие меток в группе | 35 | 7 |

- 350 позитивов Арсения — это 60 технологий × 5–11 применений («X для Y»); признаки считаются
  по технологии, поэтому такие строки — точные копии. **79 из них совпали с технологиями золота**
  (выборка строилась от примеров заказчика) — оставлять их в обучении значит мерить качество
  на том, на чём учились.
- Негативы Арсения: 410 строк N3b — программные продукты (`grafana`, `django-crm`), их отделяет
  `is_technology_flag` (среднее 0,31 против 0,95–1,0 у остальных групп).
- Классы несбалансированы (398 : 959) — при обучении нужны `class_weight="balanced"`
  или прореживание негативов Арсения.

Все 1357 строк и 100 строк золота размечены без ошибок; наука и медиа есть у всех строк
(`extraction_status` = `patents` у всех — канал выключен намеренно). Непостоянных
признаков 48 из 63.

Стадия по ленте (`llm_stage`), доли стадии 5: наши негативы — 85%, негативы Арсения — 48%,
наши позитивы — 12%, золото — 4%. 40 наших позитивов модель по ленте считает зрелыми —
кандидаты в шум меток.

### Быстрая проверка (не финальное обучение)

Логистическая регрессия на 48 непостоянных признаках, медианная импутация, стандартизация,
`C=0.3`, `class_weight="balanced"`, `StratifiedGroupKFold(5)` по `technology_group_id`:

| | AUC | Precision | Recall | F1 |
|---|---:|---:|---:|---:|
| CV, вся выборка | 0,947 | 0,770 | 0,910 | 0,834 |
| CV, только наши строки | 0,912 | | | |
| CV, только строки Арсения | 0,982 | | | |
| Золото, 100 позитивов (обучение на всей выборке) | | | 0,94 | |

Крупнейшие веса: `is_technology_flag` +2,33, `stage_scaling_or_mature` −0,99,
`paper_growth_2y` +0,79, `stage_research` +0,72. Более высокий AUC на строках Арсения —
следствие лёгких N3b-негативов; наши трудные негативы (зрелые «родители») разделяются хуже,
и именно на них стоит настраивать модель.


## 4. Известные ограничения

- Стадия в признаках — оценка LLM по заголовкам; на золоте такой судья занижает стадию
  примерно на один уровень.
- Негативы у нас в основном N1 (зрелые); N2 (хайп) и N3b (продукт вместо технологии) почти
  целиком приходят из выборки Арсения — модель может учить «продукт → негатив» по
  `is_technology_flag`. Это верное правило, но оно не про стадию.
- Около 10% наших позитивов подтверждены только медиа (научных работ по термину нет) —
  это самые ранние сигналы, как и 18% золота.
- Google News отдаёт до 100 записей на окно: объём медиа у зрелых технологий упирается
  в потолок и различает их хуже, чем ранние.
- Срез 2026-09-22 зафиксирован; источники со временем переиндексируются, поэтому
  точное воспроизведение гарантирует кэш, а не повторный сбор из сети.

## 5. Валидация на золоте

В золоте только позитивы, поэтому к нему добавлены 92 негатива (`ml/datasets/validation_negatives.csv`,
`ml/scripts/build_validation_set.py`): 55 зрелых «родителей» технологий золота
(`contrastive_negatives.py --from-gold`, стадия 5 по Википедии) и 37 наших резервных негативов
тех же областей. Ни одна технология не пересекается с обучением. Квоты по областям — как в золоте
(в «Защите ИИ» набралось 8).

`ml/scripts/train_eval.py`: C и порог выбираются групповой CV только на обучении, валидация
используется один раз.

| Обучение | Строк | Precision | Recall | F1 | ROC-AUC |
|---|---:|---:|---:|---:|---:|
| Объединённый | 1357 | 0,876 | 0,92 | 0,898 | 0,926 |
| Только наши | 707 | 0,869 | 0,93 | 0,899 | 0,946 |
| Только Арсения | 650 | 0,91 | 0,71 | 0,798 | 0,889 |

Ошибки, веса и разбивка по областям — `ml/reports/train_eval.md`. Оговорки: валидационные
негативы собраны тем же способом, что наши обучающие; вес `rebranding_similarity_to_mature`
получился положительным вопреки смыслу — признак нужно проверить.

## 6. Модель для сервиса

`ml/scripts/export_model.py` обучает финальную модель и пишет её в `app/ml/model/logreg_v1.json`
(медианы, стандартизация, веса, калибровка Платта, порог — без pickle). `app/ml/scorer.py` считает
вероятность чистым Python и раскладывает логит на точные вклады признаков с русскими подписями;
`score_candidate(name, domain)` = `featurize()` + оценка. Карточка модели — `ml/reports/model_card.md`.

Отбор: самый сильно регуляризованный C в пределах 0,005 CV AUC от лучшего (C=0,1). Из модели
исключены `rebranding_similarity_to_mature` (LLM ставит 0 зрелым технологиям, знак веса
противоречит смыслу) и оба признака ускорения (в паре с ростом получают вес обратного знака;
CV AUC −0,0015). Валидация (100 золота + 92 негатива): P 0,876, R 0,92, F1 0,898, ROC-AUC 0,922.
Оценка одного кандидата с нуля — около 40 с (сеть + два вызова LLM), повторная — из кэша.

## 7. Реестр источников

`app/registry/sources.json` — единственное место, где задано доверие к источникам: 17 типов
(с уровнем доверия, ролью и основанием), 353 международных и локальных домена на разных языках,
международные шаблоны государственных доменов (`.gov`, `.gov.au`, `.gouv.fr`, `.go.jp` и др.),
`.edu`, «press-release» в адресе. Его читают радар (тип и доверие документа),
признаки модели (`press_release_share_12m`, `independent_high_trust_source_count_log`,
`unverifiable_source_share`) и правило подтверждения `supports_signal()`: соцсети, блоги и
агрегаторы по ТЗ — только первичный индикатор, пресс-релиз не может быть единственным основанием.

После правки реестра признаки пересобираются из кэша без сети, затем модель переобучается:

```bash
python ml/scripts/build_training_set.py && python ml/scripts/build_validation_set.py
python ml/scripts/export_model.py
```

Переход на реестр (featurize-v2) изменил три признака; валидация: F1 0,898 → 0,903
(P 0,877, R 0,93). Сборка на Python 3.9 и 3.12 расходится в 6-м знаке одного HHI — в 3.12
`sum()` для float компенсирует ошибку округления; эталонная среда — 3.12, как в Docker.
