# Устаревший план работ: 14 дней до финальной сдачи

> Архив: команда располагает пятью днями; актуальный план находится в `../03-plan.md`.

Старт: 21.09.2026. Целевая дата готовности демо-стенда: 03.10.2026 (2 дня резерва на репетицию
питча и отладку).

Работа разбита на 5 параллельных потоков. Критический путь — WS2 (модель), потому что от него
зависит и объективная метрика, и ранжирование в открытом поиске.

## Поток WS2. Модель и метрики — критический путь (дни 1–9)

| # | Задача | DoD |
|---|---|---|
| 2.1 | Импортёр датасета: XLSX/CSV/JSON, гибкий маппинг колонок | 100 строк предоставленного датасета загружаются в `dataset_rows` |
| 2.2 | **Разметка серебряного яруса (~300 поз. / ~400 отр.)** по `docs/06-labeling-protocol.md` — стартует в день 1, критический путь | `ml/datasets/labeled.csv` + `manifest.md`, два аннотатора, **Cohen's kappa ≥ 0.7**, спорные в `disputed.csv` |
| 2.3 | Реестр признаков `schema.py` + лексиконы (стадии, тренда, маркетинга, хеджирования) | 65 признаков-кандидатов с русскими подписями, режимами Т/О/К и ожидаемым направлением |
| 2.4 | `from_row.py` — признаки режима Т и О из строки датасета | Вектор считается для всех ~800 записей серебра и 100 золотых |
| 2.5 | `from_evidence.py` — признаки из собранного корпуса | Общая схема с `from_row`, проверено на 10 кандидатах |
| 2.6 | Обучение: две ординальные головы (стадия, тренд) + бинарный логрег поверх, отбор признаков через stability selection, коррекция приора и калибровка | `make train` → `ml/artifacts/`, версия модели в БД, знаки коэффициентов совпадают с реестром |
| 2.7 | Оценка: CV, holdout, leave-one-domain-out, абляция, базовые линии | `ml/reports/metrics.md`, **F1 ≥ 0.80** |
| 2.8 | Ворота исключения G1–G5 с русскими причинами | На тестовом наборе зрелых технологий отсев 100% с внятной причиной |
| 2.9 | `explain.py` — вклады признаков, агрегация по блокам | На любой объект: 5 блочных вкладов + раскрытие до признаков с цитатами |
| 2.10 | Карточка модели `/api/model/card` | Отдаёт веса, метрики, версию, дату обучения |

**Контрольная точка дня 9:** если F1 < 0.75 — усиливаем негативы (2.2) и включаем режим
обогащения строк датасета через ETL. Резерв на это заложен в днях 10–11.

## Реестр рисков

| Риск | Вероятность | Митигация |
|---|---|---|
| Нет интернета / плохая сеть на защите | Средняя | Демо-кэш прогонов, локальный Qwen, заранее прогретый прогон |
| Формат датасета жюри отличается от ожидаемого | Средняя | Гибкий импортёр + ручное подтверждение маппинга колонок в UI |
| F1 не дотягивает до 0.75 | Средняя | Больше негативов, режим обогащения строк через ETL, резерв дней 10–11 |
| Лимиты/ключи внешних API (EPO, PatentsView) | Высокая | Ключи получить в день 1; graceful degradation; OpenAlex/arXiv работают без ключей |
| LLM выдумывает источники | Высокая без защиты | Валидатор цитат + проверка доступности URL + перегенерация; поле помечается «не подтверждено» |
| Падение одного парсера роняет прогон | — | `gather(return_exceptions=True)` + circuit breaker; закрыто тестами |
| Использование модели вне списка ТЗ | Средняя | Дефолт — разрешённая модель; в карточке модели видно, что работало |

## Открытые вопросы к команде

1. Сколько человек в команде и кто за какой поток отвечает? Планы WS1–WS4 рассчитаны на
   параллельную работу 3–4 разработчиков; при двух — сокращаем число коннекторов до 5–6 и
   упрощаем граф.
2. Есть ли ключи EPO OPS / PatentsView / GitHub? Получение занимает 1–3 дня.
3. Где разворачиваем демо-стенд (VPS с публичным адресом или ноутбук команды)?
4. Кто из команды берёт разметку? По протоколу это ~20 часов на аннотатора при двух
   аннотаторах, критический путь. При нехватке людей серебро сокращается до 400 записей
   с сохранением доли трудных негативов.
