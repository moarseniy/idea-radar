# ETL-конвейер поиска слабых сигналов

Документ описывает фактическую реализацию ETL в сервисе. Целевой критерий ТЗ сформулирован как
качество архитектуры конвейера обработки данных и отказоустойчивость парсеров. Здесь ETL означает
путь от найденного открытого материала до проверяемого кандидата и результата оценки.

## Поток данных

```text
запрос и ветки поиска
  → коннекторы открытых источников
  → общие ссылки и метаданные
  → получение и извлечение текста / аннотации API
  → нормализация, проверка даты, контроль дублей
  → кандидаты + ссылки на подтверждающие документы
  → оценка, фильтрация и ранжирование
  → сохранённый прогон, источники и результат
```

### Extract

Коннекторы в `app/radar/open_sources.py` обращаются к Bing News, GDELT, FreePatentsOnline,
Crossref, OpenAlex, arXiv, Хабру, NIH RePORTER, CORDIS,
GitHub, Hugging Face, TED, ClinicalTrials.gov и openFDA;
основной web-поиск выполняется выбранным провайдером. Для каждой ссылки сохраняются URL, заголовок,
канал обнаружения и доступные сведения о языке, стране и дате. Документы API, например аннотации
научных публикаций, передаются в общий формат без повторной загрузки страницы издателя.

### Transform

`app/radar/sources.py` проверяет URL, получает страницу, извлекает текст из HTML/PDF, ограничивает
размер ответа, сохраняет язык, дату, MIME-тип, хэш входа, хэш нормализованного текста и версию
парсера. Далее пайплайн связывает документы с кандидатами, помечает дубли и исключает источники,
не подходящие для даты оценки. Ошибки одного документа не отменяют остальные результаты.

### Load

`app/radar/store.py` сохраняет прогоны в `radar_runs`, а документы источников — в `radar_sources`;
в PostgreSQL используются JSONB-поля. В payload источника остаётся извлечённый текст, метаданные,
статус и контрольные хэши. При пустом `RADAR_DATABASE_URL` локальная разработка использует SQLite.
Кэш страниц хранит извлечённый документ и метаданные для повторного использования в течение
настроенного срока.

## Повторные попытки и circuit breaker

- API-коннекторы повторяют запросы до двух раз после первоначальной попытки при сетевых таймаутах,
  сетевых ошибках и HTTP 429/500/502/503/504. Для `Retry-After` используется заданная сервером
  задержка с верхним пределом; иначе применяется короткая экспоненциальная задержка.
- После трёх последовательных исчерпанных запросов API-коннектор открывается на 30 секунд. После
  паузы пропускается один проверочный вызов; успешный ответ сбрасывает счётчик.
- Загрузка страниц повторяет временные ошибки в рамках общего лимита времени для URL. Для домена
  статьи circuit breaker срабатывает после четырёх исчерпанных загрузок и открывается на 45 секунд.
- Постоянные HTTP-ошибки, неверный формат ответа, ошибки извлечения и нарушения URL-политики
  фиксируются без повторов. Ошибка одного коннектора или URL не останавливает остальные каналы.
- Сводка каналов в прогоне показывает число запросов, найденных ссылок и ошибок; источник хранит
  статус чтения и причину ошибки.

## Целостность и ограничения

`ingest_sha256` — SHA-256 тела HTTP-ответа до извлечения текста; для API-документа это хэш текста,
переданного парсеру. `content_hash` — хэш нормализованного извлечённого текста, применяемый для
контроля дублей. `parser_version` позволяет понять, какой версией извлечено содержимое.

Исходный HTML/PDF-ответ не копируется в базу данных. Сохраняются извлечённый текст и хэш входа;
этого хватает для проверки целостности обработанного текста, но не для повторного парсинга сырого
байтового ответа. Это ограничение нужно учитывать при строгом толковании требования ТЗ о хранении
«сырых данных». Для хранения исходных файлов потребуется отдельная политика хранения и проверки
прав на копирование каждого типа источника.

## Проверки

Тесты `tests/test_open_sources.py` проверяют повторы временной сетевой ошибки, открытие circuit
breaker, изоляцию ошибок каналов, работу многоязычных коннекторов и фиксацию хэша и версии парсера
при загрузке документа. Интеграционный прогон с реальными публичными сервисами нужно выполнять в
окружении с доступом к сети; unit-тесты внешние API не вызывают.
