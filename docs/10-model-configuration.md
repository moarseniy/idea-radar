# Настройки моделей текущего сервиса

В запросе участвуют LLM-компоненты для планирования, обработки материалов и извлечения признаков. Числовой скоринг кандидата выполняет логистическая регрессия.

## Источник текущей конфигурации

Проверенный локальный endpoint /api/radar/config сообщил: артефакт logreg_v1.json, 46 входов, порог 0,42. Текущий .env задаёт DeepSeek V4.1 Flash для извлечения признаков. API предупреждает, что артефакт обучался на другой разметке признаков; эти данные не следует считать полностью совместимыми.

Файл .env.example задаёт FEATURE_MODEL=openai/gpt-5.6-luna. С такой настройкой выбор артефакта отличается от проверенного локального сервиса и использует схему с 44 входами и порогом 0,50. Следовательно, шаблон .env и запущенный локальный сервис сейчас не совпадают. Проверяйте фактические значения в /api/radar/config перед запуском и при подготовке отчёта.

## Как выбирается артефакт

Модуль app/ml/scorer.py применяет следующий порядок:

1. SIGNAL_MODEL_PATH, если явно задан.
2. logreg_v1_<имя модели признаков>.json, если такой совместимый файл существует.
3. Основной артефакт, если его поле feature_model совпадает с FEATURE_MODEL.
4. Резервный logreg_v1.json, если подходящего совпадения нет.

После смены FEATURE_MODEL проверьте warning и поле scoring в /api/radar/config. Совпадение размерности входов само по себе не гарантирует совместимость: значения могут иметь другое распределение.

## Локальная LLM

RADAR_PROVIDER=local направляет вызовы радара на OpenAI-совместимый сервер, например Ollama, vLLM, SGLang или LM Studio. Для локального извлечения признаков отдельно задаются FEATURE_MODEL и FEATURE_LLM_URL. Доступные совместимые артефакты указаны в app/ml/model/; соответствие модели извлечения признаков выбранному скорингу необходимо проверять по API.

Пошаговый запуск через Ollama и Docker Compose приведён в [инструкции развёртывания](13-local-deployment.md); полный перечень переменных — в [.env.example](../.env.example).
