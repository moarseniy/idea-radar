# Канонический реестр признаков

Этот документ — единственный актуальный источник правды о признаках модели.

**Итоговый пул: 58 содержательных признаков + 5 индикаторов пропусков = 63 логических признака-кандидата.** После отбора финальная бинарная логистическая регрессия должна содержать ориентировочно 18–25 логических признаков. One-hot и spline-преобразования могут увеличить число физических колонок матрицы, но не число логических признаков.

## 1. Объект, дата и цель

Единица наблюдения:

```text
конкретная технология × конкретное применение × snapshot_date
```

Например, «федеративное обучение» слишком широко; «федеративное обучение для межбанковского AML без передачи сырых данных» — подходящий объект.

Цель основной модели:

- `1` — слабый сигнал на дату среза;
- `0` — зрелая технология, хайп/шум, недостаточно подтверждённый или нерелевантный кандидат.

Причина нулевого класса хранится отдельно. Жёсткие ворота зрелости, отсутствия технического содержания и нерелевантности применяются до модели и всегда возвращают объяснение.

Все источники и события должны быть доступны системе не позднее `snapshot_date`. Дата события внутри документа не заменяет дату публикации/доступности документа.

## 2. Общие правила вычисления

### 2.1 Временные окна

- наука и патенты: основные окна 24 и 36 месяцев, динамика по кварталам;
- медиа: 6 и 12 месяцев;
- финансирование и пилоты: 24 месяца;
- гранты: 36 месяцев.

Если задача использует другой горизонт, создаётся новая версия схемы признаков. Нельзя менять окно между обучением и инференсом.

### 2.2 Преобразования

Счётчики преобразуются как `log1p(x)`. Рост канала `c`:

```text
growth_c = log1p(count_c[current_window]) - log1p(count_c[previous_window])
```

Ускорение:

```text
acceleration_c = growth_c(current_pair) - growth_c(previous_pair)
```

Абсолютные объёмы дополняются перцентилем внутри области и даты. Сырые counts разных отраслей напрямую не сравниваются.

### 2.3 Пропуски

Отсутствующее значение хранится как `NaN`, рядом вычисляется `missing_*`. «Источник не покрывает объект» не равно фактическому нулю.

Для логистической регрессии числовое заполнение выполняется медианой **только внутри обучающего fold**. Индикаторы пропусков проходят отбор как обычные признаки.

### 2.4 Направления

- `+` — рост ожидаемо повышает вероятность слабого сигнала;
- `−` — рост ожидаемо понижает вероятность;
- `∩` — немонотонность: слабому сигналу соответствует промежуточный диапазон;
- `ctx` — знак зависит от сочетания с другими признаками; направление проверяется экспериментом.

Признаки `∩` кодируются квантильными bins или натуральным spline внутри обучающего pipeline. Границы запрещено рассчитывать по полной выборке.

### Исключено из общего реестра

- Wikipedia age/no-Wikipedia: зависит от популярности и редакторов, дублирует видимость;
- отсутствие устоявшегося русского термина: языковая и географическая систематическая ошибка;
- Google Trends baseline: нестабильный доступ и плохо воспроизводимый ряд;
- institution elite share: произвольный рейтинг создаёт географический и репутационный bias;
- субъективный `tier1_investor_flag`: заменён воспроизводимым числом стратегических инвесторов;
- GitHub age/stars как общий признак: неприменим к материалам, оборудованию и закрытому industrial tech; допустим только в отдельной доменной модели ПО;
- hedging density: хеджирование встречается и в добросовестной науке, и в пустом маркетинге; знак нестабилен;
- `competitive_leaders_named`: заменён наблюдаемыми `A10`, `A11`, `A14`, `A15`;
- `low_volume_flag`: дублировал перцентиль; низкий/средний диапазон моделируется bins;
- отдельные counts tier A/max/mean trust: заменены одним проверяемым числом независимых высокодоверенных источников;
- `concept_breadth`: нестабилен при изменении таксономии OpenAlex; межотраслевость оценивается отдельно в аналитическом отчёте.

### Отложено до анализа ошибок baseline

- вакансии и рост требований к навыкам: нужен отдельный стабильный корпус вакансий;
- package downloads и GitHub contributors: только для доменной модели ПО;
- `funding_per_patent` и `funding_per_pilot`: нестабильны при малом знаменателе и дублируют базовые counts;
- отдельная `media_acceleration`: при коротком ряде сильно коррелирует с `D02` и `D03`;
- `patent_minus_media_growth`: частично дублирует `G03`; возвращается только при подтверждённой добавочной ценности;
- расстояние новых документов до исторического centroid: требует замороженной embedding-модели и отдельной проверки дрейфа;
- доля новых коммерческих поставщиков: добавляется после появления качественного реестра компаний;
- произвольные парные произведения базовых признаков. В первой версии их заменяют интерпретируемые `G01–G05`; новые interactions добавляются только как заранее описанный эксперимент внутри CV.

## 5. Режимы доступности

| Режим | Назначение | Доступные блоки |
|---|---|---|
| `offline_features` | быстрый расчёт структурных признаков из локальных/кэшированных evidence | доступные блоки A–G; неполные каналы помечаются как пропуски |
| `enriched` | пакетная оценка кандидатов с API | A–G |
| `open_search` | корпус открытого запроса | A–G и provenance каждого значения |

Метрики режимов доступности evidence публикуются отдельно. Структурная модель получает только числовой вектор из этого реестра; текстовые n-граммы не используются при обучении.

## 6. Отбор в финальную модель

Все шаги выполняются внутри внутреннего цикла вложенной групповой временной CV:

1. Удалить признаки с пропусками >70%, если соответствующий `missing_*` неинформативен.
2. Удалить почти константные признаки.
3. Для пар с `|r| > 0.85` оставить более воспроизводимый и дешёвый признак; univariate AUC используется только внутри train fold.
4. Провести stability selection: бутстрэп + L1-логрег.
5. Подобрать число признаков и регуляризацию во внутренней CV.
6. Обучить L2-логрег на отобранных признаках.
7. Проверить устойчивость коэффициентов и ожидаемые знаки. Для `∩` и `ctx` проверять форму/стабильность, а не один знак.
8. Калибровать вероятность только на отдельной calibration-части или через корректную cross-validation схему.

Связанные технологии, aliases, патентные семейства и перепечатки одного события группируются и не разделяются между train/test. Для финальной оценки нужен временной holdout.

## 7. Интерпретация

Локальный вклад физической колонки:

```text
contribution_j = transformed_feature_j × coefficient_j
```

В UI вклады сначала суммируются по семи смысловым блокам, затем раскрываются до признаков. Для каждого признака показываются исходное значение, окно, дата среза, источник и подтверждающий фрагмент при текстовом извлечении.

Коэффициенты не являются причинными эффектами. Некалиброванный `predict_proba` не называется уверенностью 87%.

## 8. Запрещённые признаки

- колонка Excel «Почему это слабый сигнал»;
- авторский балл и позиция строки;
- число ссылок из исходной таблицы;
- итоговое решение или score LLM;
- идентификатор разметчика, источник файла, шаблон позитивного/негативного примера;
- сведения, опубликованные после `snapshot_date`;
- числа, сгенерированные LLM вместо API/реестра;
- counts до дедупликации DOI, патентных семейств и перепечаток.

## 9. Версионирование

Для каждой строки сохраняются:

```text
feature_schema_version
technology_application_id
snapshot_date
query_alias_version
raw_channel_counts
transformed_features
missing_flags
source_ids
computed_at
```

Изменение aliases, окна, источника или формулы создаёт новую версию признака и требует переобучения.
