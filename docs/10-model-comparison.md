# Выбор LLM для разметки признаков и локальный запуск

Метрики в этом сравнении относятся к модели, используемой сервисом, и валидации на 98 позитивных
и 89 негативных примерах. Сводные результаты модели и протокол их получения приведены в
[12-final-metrics.md](12-final-metrics.md).

LLM в разметке признаков (`app/ml/features/extract.py`) делает три вещи:
- решает, технология ли это («технология, а не продукт или бренд»);
- выписывает события из заголовков новостей (пилоты, внедрения, раунды, стандарты);
- оценивает стадию и массовость.

Модель слабых сигналов учится на этих признаках, поэтому качество LLM напрямую влияет на её
качество. Здесь сравнены облачные модели из списка ТЗ и открытые модели, которые можно запустить
на своём железе.

Итог:
- **По умолчанию разметку делает `openai/gpt-5.6-luna`.** Она из списка ТЗ, даёт F1 0,856
  на валидации и по оценке LLM-судьи читает заголовки не хуже прежней gemini.
- **Для работы без внешнего API — `RADAR_PROVIDER=local`.**
  - `qwen3.6:35b-a3b`: из списка ТЗ, быстрая, F1 0,816 (облачные признаки) и 0,840 (признаки,
    размеченные на ноутбуке).
  - `qwen3.8:27b`: лучшая открытая модель, F1 0,847, но её нет в списке ТЗ — нужно согласование.

## 1. Как сравнивали

`ml/scripts/compare_feature_models.py`. Для всех моделей одинаковы:
- **Данные:** поисковый термин, статьи Crossref и заголовки Google News берутся из базовой сборки.
- **Строки:** 1514 технологий — обучение плюс валидация. Строки, на которых хотя бы одна модель
  не ответила, исключены у всех.
- **Обучение и валидация:** общий код `export_model.fit`, так же подбираются C, калибровка и порог.

Меняется только LLM. Разница в метриках — это разница в том, как модель прочитала одни и те же
заголовки, а не в том, что поисковик нашёл по другому термину. Проверка корректности: базовая
модель (gemini) воспроизводит признаки базовой сборки из кэша без единого расхождения.

Суффикс `#nothink` означает режим без рассуждений. Для ноутбука это обязательно: Qwen3.8-27B тратит
на короткий ответ около 1,4 тыс. токенов «размышлений», Nemotron — около 5,8 тыс. На ноутбуке это
минуты на вызов.

## 3. LLM-судья: качество чтения

Метрики модели меряют качество целиком. Судья проверяет само извлечение
(`ml/scripts/judge_extractions.py`):
- судья — `anthropic/claude-opus-5.5`, другое семейство, чем у всех кандидатов;
- выборка — 116–119 строк: примеры заказчика, валидационные негативы и обучение;
- ответы моделей стоят под буквами в случайном порядке, судья не знает, где чья модель.

Для каждого события судья проверяет, есть ли оно в указанном заголовке и верен ли тип. Также он
считает пропущенные события и оценивает обоснованность стадии и признаков «технология» и
«массовость».

Прогон 1 — облачные модели (119 строк):

|---|---:|---:|---:|---:|---:|---:|
| gpt-5.6-luna | 0,90 | 0,62 | 4,1 | 0,99 | **6,44** | **30%** |
| gemini-3.8-flash | 0,94 | 0,46 | 4,1 | 0,99 | 6,32 | 26% |

| Qwen3.6-35B-A3B (с рассуждениями) | 0,64 | 0,53 | 3,9 | 0,97 | 5,55 | 20% |
| Qwen3 235B-A22B | 0,57 | 0,87 | 3,5 | 0,97 | 5,17 | 9% |

| LLM | Точность событий | Полнота событий | Событий на строку | Стадия обоснована (1–5) | Общая (1–10) | Доля побед |
|---|---:|---:|---:|---:|---:|---:|

**Выводы:**
- **luna, Qwen3.8-27B и Gemma 4 31B читают на одном уровне.**
- **Gemini точнее всех, но пропускает больше всех.**
- **Маленькие MoE без рассуждений выписывают события, которых нет в заголовках.** Это Qwen3.6-35B-A3B,
  Gemma 26B-A4B и Nemotron с 3–4B активных параметров. Модель слабых сигналов на таком шуме теряет
  3–7 пунктов F1.

**Проверка самого судьи:**
- Его стадия на 37 примерах заказчика совпадает со стадией заказчика в 41% случаев, с ошибкой не
  больше единицы — в 81%. Это тот же уровень, что у лучших моделей: стадия по заголовкам
  неоднозначна и для сильной модели.
- Смещение из-за порядка ответов — до 0,6 балла между позициями. Порядок случайный для каждой
  строки, так что на сравнение это не влияет.

## 4. Локальный запуск

Сценарий развёртывания без внешнего API:
- модель слабых сигналов обучена на признаках от полных весов открытой LLM;
- в сервисе признаки размечает квантизованная версия той же LLM на локальном сервере.

Для каждой открытой модели экспортирован свой артефакт:
- `app/ml/model/logreg_v1_qwen3.6-35b-a3b.json` (F1 0,816);
- `app/ml/model/logreg_v1_qwen3.8-27b.json` (F1 0,847).

Сервис выбирает артефакт по `LOCAL_MODEL`.

Замер на MacBook M5, 32 ГБ, Ollama 0.34, веса Q4 по умолчанию: `qwen3.6:35b-a3b` занимает 22 ГБ,
`qwen3.8:27b` — 17 ГБ. Проверка — `ml/scripts/local_model_check.py`. Модель скоринга обучена на
облачных признаках, валидация размечается второй раз на ноутбуке.

**qwen3.6:35b-a3b (из списка ТЗ): вся валидация, 187 строк** (`ml/reports/local_model_check_qwen3.6-35b-a3b.md`):

| Признаки валидации | P | R | F1 | ROC-AUC |
|---|---:|---:|---:|---:|
| облако (полные веса) | 0,728 | 0,929 | 0,816 | 0,863 |
| ноутбук (Q4) | 0,781 | 0,908 | **0,840** | 0,883 |

- **Совпадение с облаком:** решение модели — 92%, стадия — 73%, признак «технология» — 100%.
  Средняя разница вероятностей 0,08.
- **Качество не падает.** F1 на квантизованных весах даже чуть выше. Это разброс в пределах шума
  на 187 строках, а не выигрыш от квантизации.
- **Время:** медиана 26 с на технологию при 2 параллельных запросах, то есть около 13 с на строку;
  p90 — 64 с.

**qwen3.8:27b (dense): пробные 4 строки.** Решение совпало с облаком 4 из 4, время около 83 с на
2 параллельных запроса, то есть около 40 с на строку. Полная проверка была прервана — Ollama
остановили по ходу работы.

Для радара это значит: 32 кандидата размечаются примерно за 7 минут на Qwen3.6-35B-A3B и примерно
за 20 минут на Qwen3.8-27B. Для ноутбука это медленно, но работает. На одном серверном GPU (vLLM)
обе модели быстрее облака.

Повторить или дополнить проверку:

```bash
ollama serve &
python ml/scripts/local_model_check.py --local qwen3.6:35b-a3b --cloud "qwen/qwen3.6-35b-a3b#nothink"
python ml/scripts/local_model_check.py --local qwen3.8:27b --cloud "qwen/qwen3.8-27b#nothink"
```

### Радар целиком в режиме `local`

Проверен живой прогон «Слабые сигналы в финансовых технологиях для банков» с
`RADAR_PROVIDER=local`. Роль «локального сервера» играл OpenRouter с теми же весами
Qwen3.6-35B-A3B без рассуждений: протокол тот же, OpenAI-совместимый.

| | Облако (gpt-4.1 + веб-поиск) | `local`, Qwen3.6-35B-A3B |
|---|---:|---:|
| Источников найдено / прочитано | 213 / 54 | 147 / 58 (только открытые коннекторы) |
| Кандидатов | 24 | 32 |
| Вызовов LLM / с ошибкой | — | 17 / 0 |
| Подтверждённых сигналов в ТОП | 15 | 6 |
| Время | 5,2 мин | 5,5 мин |

- **Слабое место локального режима — этап проверки источников, а не модель скоринга.** Модель
  скоринга признала сигналами большинство кандидатов.
- **Цитаты находятся, но отношение ставится не то.** Открытая модель без рассуждений находит
  дословные цитаты, но чаще помечает их как «контекст», а не «основание». Правило требует хотя бы
  одного подтверждающего источника, и мы его не ослабляем.
- **Смысловое объединение кандидатов не проходит проверку схемы.** В этом случае применяется
  консервативная дедупликация названий.
- **Искажённые id исправлены в пайплайне.** Открытая модель переписывала id кандидатов
  (`cand_d1977acd71c8`), поэтому оценки не находили своих кандидатов. Теперь нераспознанные
  оценки сопоставляются по порядку (`match_assessments`). С этим исправлением подтверждённых
  сигналов стало 6 вместо 2.

Для полного ТОП-15 без облака нужна модель сильнее на проверке: Qwen3.8-27B или Qwen3.6-35B-A3B
с рассуждениями на GPU-сервере.

## 5. Как включить

| Режим | Настройки `.env` | Разметка признаков | Модель скоринга |
|---|---|---|---|
| По умолчанию | `FEATURE_MODEL=openai/gpt-5.6-luna`, `OPENROUTER_API_KEY` | luna через OpenRouter | `logreg_v1.json` (F1 0,856) |
| Локально, список ТЗ | `RADAR_PROVIDER=local`, `LOCAL_MODEL=qwen3.6:35b-a3b` | Ollama/vLLM без рассуждений | `logreg_v1_qwen3.6-35b-a3b.json` (F1 0,816) |
| Локально, лучшее качество | `RADAR_PROVIDER=local`, `LOCAL_MODEL=qwen3.8:27b` | Ollama/vLLM без рассуждений | `logreg_v1_qwen3.8-27b.json` (F1 0,847) |

LLM поиска и LLM разметки признаков настраиваются независимо (`app/ml/env.py`):
- **`RADAR_PROVIDER`** отвечает за поиск: план запросов, выделение кандидатов, проверку источников.
  При `local` веб-поиска нет, и ссылки дают открытые коннекторы: Bing News EN/RU, Crossref, arXiv
  и Хабр.
- **`FEATURE_MODEL` и `FEATURE_LLM_URL`** отвечают только за разметку признаков. Если их не задавать,
  разметка идёт туда же, куда поиск: luna в облаке или `LOCAL_MODEL` при `local`.
- **Модель скоринга выбирается по LLM разметки,** а не по `RADAR_PROVIDER`:
  `logreg_v1_<LLM разметки>.json`, если такой артефакт есть, иначе основная `logreg_v1.json`.
  Если LLM разметки и обучающие данные модели не совпадают, `/api/radar/config` показывает
  предупреждение. `SIGNAL_MODEL_PATH` задаёт артефакт явно.
- **Ключи не уходят на чужие адреса.** `OPENROUTER_API_KEY` отправляется только в OpenRouter,
  `LOCAL_LLM_KEY` — только на `LOCAL_LLM_URL`.

| Поиск | Разметка признаков | Настройки `.env` | Модель скоринга (автоматически) |
|---|---|---|---|
| облако | облако | `RADAR_PROVIDER=openrouter` | `logreg_v1.json` |
| облако | локально | `RADAR_PROVIDER=openrouter`, `FEATURE_MODEL=qwen3.6:35b-a3b`, `FEATURE_LLM_URL=http://localhost:11434/v1` | `logreg_v1_qwen3.6-35b-a3b.json` |
| локально | облако | `RADAR_PROVIDER=local`, `FEATURE_MODEL=openai/gpt-5.6-luna`, `FEATURE_LLM_URL=https://openrouter.ai/api/v1` | `logreg_v1.json` |
| локально | локально | `RADAR_PROVIDER=local`, `LOCAL_MODEL=qwen3.6:35b-a3b` | `logreg_v1_qwen3.6-35b-a3b.json` |

Для смешанных режимов по результатам выше разумнее такое сочетание: поиск в облаке, а разметка
признаков — локально. Проверка источников — самое слабое место открытой модели. Разметка на
ноутбуке качества почти не теряет: F1 0,840, решения совпадают с облаком в 92% случаев.

Воспроизведение:

```bash
python ml/scripts/compare_feature_models.py              # все модели; ответы LLM в кэше
python ml/scripts/judge_extractions.py --models "..."    # судья по выбранным моделям
python ml/scripts/export_model.py --data ml/datasets/model_compare/gpt-5.6-luna
python ml/scripts/export_model.py --data ml/datasets/model_compare/qwen3.6-35b-a3b-nothink \
  --out app/ml/model/logreg_v1_qwen3.6-35b-a3b.json
```
