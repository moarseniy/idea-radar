# Протокол разметки обучающей выборки

Документ предназначен для аннотаторов бинарной модели слабых сигналов.

## 1. Единица разметки

Размечается:

```text
конкретная технология × конкретное применение × дата среза
```

| Хорошо | Плохо | Причина |
|---|---|---|
| Identity & access management для ИИ-агентов | Keycard | продукт/компания |
| Электрогидравлические искусственные мышцы для мягких роботов | искусственные мышцы | слишком широко |
| Постквантовая криптография в банковской платёжной инфраструктуре на 2024-12-31 | постквантовая криптография | нет применения и даты |

Основные шесть областей Excel сохраняются для сопоставимости. Для обобщения добавляются технологии из других областей, которые может запросить жюри. Домен не должен определять метку.

## 2. Поля разметки

Каждый аннотатор независимо заполняет:

- `label`: 1/0/abstain;
- `snapshot_date`;
- `stage`: research, poc, pilot, early_adoption, scaling_or_mature, unknown;
- `trend`: declining, stable, growing, accelerating, unknown;
- `negative_type`: пусто для позитива либо N1–N3e;
- краткое обоснование;
- evidence IDs и цитаты;
- уровень уверенности аннотатора: high/medium/low;
- известные противоречия.

`stage` и `trend` — вспомогательная разметка для контроля качества и анализа ошибок. Они не являются отдельными головами актуальной модели.

## 3. Положительный пример

Все условия должны быть выполнены:

1. Объект является технологией/методом в конкретном применении.
2. На дату среза есть исследовательский переход, прототип, PoC, пилот или первые ограниченные внедрения.
3. Есть значимое новое изменение или положительная динамика хотя бы в одном содержательном канале.
4. Есть техническое свидетельство: работа, патент, документация, репозиторий, измеримый прототип или описанный пилот.
5. Нет подтверждения массового распространения именно применения.
6. Возможная значимость сформулирована конкретно, без требования доказать будущий успех.

Один сильный первичный источник допустим для очень раннего результата. Аннотатор обязан поставить `evidence_limit=single_primary`. Два и более независимых источника предпочтительны. Перепечатки одного анонса считаются одним свидетельством.

## 4. Отрицательные примеры

| Код | Тип | Определение |
|---|---|---|
| N1 | зрелая технология | массовое внедрение, сформированный рынок или зрелый стандарт именно применения |
| N2 | хайп/маркетинг | высокая медийность без технического свидетельства |
| N3a | нишевая зрелость | малый объём упоминаний, но давно сложившийся узкий рынок |
| N3b | подмена сущности | компания, продукт, персона или отрасль вместо технологии |
| N3c | ребрендинг | зрелая технология под новым названием |
| N3d | растущая массовая | высокая динамика при уже широком внедрении |
| N3e | исследование без движения | длительная академическая тема без перехода стадии или нового изменения |

Недостаток данных не принуждается к нулю: используется `abstain`. Такие объекты полезны для тестирования отказа от решения, но не входят в supervised training до разрешения неопределённости.

Рекомендуемый состав негативов: 30–35% N1, 20–25% N2, остальные — трудные N3.

## 5. Ярусы данных

| Ярус | Содержание | Назначение |
|---|---|---|
| benchmark организаторов | 100 положительных примеров Excel | recall/coverage позитивов и качественный анализ |
| серебро | самостоятельно собранные позитивы и негативы, два аннотатора | train и nested CV |
| золотой holdout | отложенные позитивы и негативы, не участвующие в разработке | финальные бинарные метрики |
| бронза | псевдоразметка основной моделью, часть проверена человеком | дополнительное обучение с низким весом |

100 строк организаторов не называются бинарным holdout: отрицательного класса в них нет, а таблица уже использовалась при проектировании методологии.

## 6. Процедура

1. Зафиксировать aliases, применение и snapshot date до сбора evidence.
2. Собрать документы одним ETL для позитивных и отрицательных кандидатов.
3. Два аннотатора независимо ставят метку и вспомогательные поля.
4. Рассчитать Cohen's kappa без `abstain`. Ориентир приёмки — κ ≥ 0.7.
5. Разногласия рассматривает третий участник. Неразрешённые записи остаются `abstain`.
6. Группы связанных применений, aliases, патентных семейств и событий фиксируются для split.
7. После заморозки holdout его примеры нельзя использовать для словарей, aliases, порогов и отбора признаков.

## 7. Запрещённые источники признаков

- «Почему это слабый сигнал», авторский балл, номер и место строки Excel;
- количество ссылок, подготовленное разметчиком;
- текст rationale аннотатора;
- идентификатор аннотатора и источник набора;
- числа, придуманные LLM;
- документы после snapshot date.

Ссылки Excel используются только как подсказка для ручной проверки. Для вычисления признаков evidence пересобирается текущим ETL.

## 8. Формат

`ml/datasets/labeled.csv`:

```text
id,technology_name,application,domain,snapshot_date,label,stage,trend,
negative_type,evidence_limit,annotator_confidence,group_id,
annotator_1,annotator_2,agreed,adjudicated,evidence_ids,added_at
```

Rationale и подробные цитаты хранятся отдельно от таблицы признаков, чтобы случайно не попасть в модель.

## 9. Контроль качества

- минимум 20% записей — пограничные;
- одинаковая процедура evidence для классов;
- сравнимое распределение доменов и дат;
- аудит 10% согласованных меток третьим участником;
- отдельный отчёт по `abstain` и причинам;
- проверка на утечку шаблонов, числа ссылок и домена;
- manifest содержит dataset hash, версии протокола и сборщика.

## 10. Объём

Желаемая цель — около 300 позитивов и 400 негативов. При ограничении хакатона важнее собрать меньший набор с качественными near-miss негативами и отдельным временным holdout, чем сотни очевидных или синтетических примеров.
