# IDEA

## Технологический радар

Главная страница открывает поиск ранних технологических сигналов: многоязычный план → открытые источники → чтение документов → кандидаты → проверка зрелости → финальный ТОП-15 кандидатов и отчёты. Сначала в списке идут подтверждённые слабые сигналы по убыванию уверенности; затем, если их меньше 15, остальные кандидаты также по убыванию уверенности. Исходный статус каждого сохранён. Исходное приложение гипотез сохранено на `/lab`.

### Быстрый запуск

```bash
cp .env.example .env
# Заполните OPENROUTER_API_KEY в .env
docker compose up --build -d
```

Откройте [http://localhost:8080](http://localhost:8080). Compose запускает PostgreSQL и API. Облачный LLM-шлюз проекта — OpenRouter; он используется радаром и старым разделом `/lab`. Без внешнего API — `RADAR_PROVIDER=local` (открытая модель на своём сервере, см. ниже). Модель `openai/gpt-4.1` — это выбранная модель внутри OpenRouter, а не прямой вызов OpenAI API. Автоматическая маршрутизация моделей отсутствует.

Без ключа доступны интерфейс, каталог 100 примеров и сохранённые исследования. Поиск возвращает понятную ошибку настройки, а не вымышленные результаты. Каталог и его авторские оценки не используются как готовые ответы нового поиска.

### Локальная разработка

```bash
cp .env.example .env
# Укажите OPENROUTER_API_KEY в .env
uv venv .venv --python 3.12
uv pip install --python .venv/bin/python -r requirements-dev.txt
cd frontend && npm ci && npm run build && cd ..
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8080
```

Конфигурация радара читает `.env` при запуске каждого нового поиска. При пустом `RADAR_DATABASE_URL` используется явно обозначенное в API локальное SQLite-хранилище `storage/radar.db`; для стенда Compose задаёт PostgreSQL. Один процесс Uvicorn управляет заданиями. Несколько независимых API workers пока не поддерживаются. Незавершённые задания после рестарта помечаются прерванными и могут быть повторены.

### Запуск в Docker Compose

```bash
cp .env.example .env            # ключ: OPENROUTER_API_KEY (или RADAR_PROVIDER=local — без внешнего API)
docker compose up -d --build    # PostgreSQL + API + интерфейс, http://127.0.0.1:8080
```

Порт меняется `RADAR_PORT` (например, `RADAR_PORT=8092 docker compose up -d`). Запуски, источники
и оценки хранятся в PostgreSQL, кэш признаков — в `storage/feature_cache`.

### Интерфейс (React)

Интерфейс — `frontend/` (Vite + React + TypeScript), подробности в `frontend/README.md`.
Локально: `cd frontend && npm ci && npm run build`, затем запуск API как обычно — интерфейс
откроется на `/`. В Docker собирается автоматически. Прежняя страница доступна на `/legacy`.

### Поиск кандидатов

Каждая ветка плана ищется общим веб-поиском и открытыми источниками. Веб-поиск — сервис
`app/search` (контейнер `search`): провайдер выбирается в `.env` (`SEARCH_PROVIDERS`: SearXNG по
умолчанию, Tavily, Exa, Brave, Yandex Search API, OpenSERP, веб-плагин OpenRouter), цепочкой с
запасными — [docs/11-search.md](docs/11-search.md). Открытые источники
(`app/radar/open_sources.py`): Bing News и Crossref по 14 приоритетным языкам, FreePatentsOnline,
OpenAlex, NIH RePORTER, CORDIS, GitHub, Hugging Face, TED,
ClinicalTrials.gov и openFDA, а также arXiv (EN), Хабр (RU) и GDELT Global News. GDELT ищет
по английской формулировке среди машинно-переведённых
материалов десятков языков; его API ограничен скользящим окном примерно в три месяца. Модель также
добавляет язык исходного запроса пользователя, если его код известен. Для каждого
языка используются локальные запросы и региональные настройки Bing. Гранты, тендеры и реестры
испытаний поступают из структурированных API; документы сохраняют оригинальный заголовок, URL,
дату и определённый язык. Статьи GDELT загружаются с сайтов-издателей и проходят ту же
проверку, что и остальные документы. Это широкий международный охват, не буквальное покрытие всех
существующих языков. На проверке стадии по каждому
кандидату дополнительно ищутся новости Bing о пилотах и внедрениях. Ссылки всех каналов
перемешиваются по очереди; лимит чтения — 110 документов, кандидатов — до 60. Отключить открытые
источники: `RADAR_OPEN_SOURCES=0`. Сводка по каналам — в разделе «Как получен результат».
OpenAlex в текущей конфигурации отключён из-за повторных `429`; чтобы включить его вручную,
установите `OPENALEX_ENABLED=1`. Crossref, прямой arXiv и остальные перечисленные коннекторы
продолжают работать.

ТОП-15 сначала включает слабые сигналы по убыванию уверенности, затем дополняется остальными
проверенными кандидатами по убыванию уверенности. В нём сохраняется вердикт проверки: зрелость,
нерелевантность или недостаточность доказательств не превращаются в позитивную метку. Отдельная
вкладка показывает только слабые сигналы. Кандидаты одной технологии, найденные
среди подтверждённых слабых сигналов, склеиваются; дополнительные применения остаются у лидера.

### Конвейер ETL и устойчивость источников

Сборщик приводит ответы коннекторов и загруженные страницы к общей записи источника, сохраняет
извлечённый текст, метаданные, хэш входного содержимого и версию парсера, затем связывает документ
с кандидатами и оценками. Временные сетевые ошибки повторяются ограниченное число раз; повторные
сбои временно открывают circuit breaker для API-коннектора или домена статьи, а другие источники
продолжают обрабатываться. Результаты и статусы каналов сохраняются вместе с прогоном. Подробности,
включая границы хранения исходного ответа, описаны в [ETL-документации](docs/09-etl.md).

Будущий сбор обучающих кандидатов в `ml/scripts/collect.py` использует тот же список языков.
Чтобы не умножать стоимость Tavily на все языки для каждого поискового угла, он детерминированно
распределяет локали по областям: русский и английский всегда, ещё четыре языка — по циклу; суммарно
по шести областям покрывается весь приоритетный список. Уже собранная выборка и модель не меняются,
пока коллекцию отдельно не пересоберут и модель не переобучат.

### Скоринг обученной моделью

Решение по кандидату принимает логистическая регрессия (`app/ml/model/logreg_v1.json`, карточка —
`ml/reports/model_card.md`). Сразу после выделения кандидатов `app/radar/model_scoring.py` параллельно
размечает их 63 признаками (`app/ml/features/extract.py`: Crossref и OpenAlex, FreePatentsOnline,
Google News, NIH RePORTER и CORDIS для грантов, LLM — `FEATURE_MODEL`)
и считает калиброванную вероятность со вкладами признаков. LLM-проверка источников остаётся: она
отсеивает нерелевантное запросу и кандидатов без дословно подтверждённых цитат. Скоринг = вероятность
модели в процентах; в отчёте — блок «Почему модель так решила». Отключить модель: `RADAR_USE_MODEL=0`.

Разметке признаков нужен `OPENROUTER_API_KEY` (модель `FEATURE_MODEL`, по умолчанию
`openai/gpt-5.6-luna` — из разрешённого списка; выбор — [docs/10-model-comparison.md](docs/10-model-comparison.md)).
Патентный канал использует только FreePatentsOnline: поиск по датам
подачи и ссылки на найденные документы. Если FPO недоступен, патентные признаки остаются
пропущенными, а поиск сообщает об ошибке источника; пропуски не подменяются нулевыми значениями.
Google Patents BigQuery удалён из проекта: публичный набор содержит данные только по 2018 год
включительно и не подходит для поиска свежих технологических сигналов. Модель радара берётся
из разрешённого списка:

```bash
RADAR_DEADLINE_SECONDS=1200 .venv/bin/python -m uvicorn app.main:app --port 8091
```

### Локальная модель без внешнего API

`RADAR_PROVIDER=local` переводит на свой OpenAI-совместимый сервер (Ollama, vLLM, SGLang, LM Studio)
и радар, и разметку признаков; `LOCAL_LLM_BACKEND` выбирает, как у сервера выключаются рассуждения.
Веб-поиск остаётся — сервис поиска с SearXNG без ключей, так что весь стек работает на своём железе;
модель скоринга берётся обученная на признаках той же LLM (`app/ml/model/logreg_v1_<модель>.json`).
Выбор модели и измеренное качество — [docs/10-model-comparison.md](docs/10-model-comparison.md).

```bash
brew install ollama && ollama serve &          # или vLLM на GPU-сервере
ollama pull qwen3.6:35b-a3b                    # из списка ТЗ; лучшее качество — qwen3.8:27b
RADAR_PROVIDER=local LOCAL_MODEL=qwen3.6:35b-a3b RADAR_DEADLINE_SECONDS=2400 \
  .venv/bin/python -m uvicorn app.main:app --port 8091
```

В Docker Compose сервер на хосте доступен как `http://host.docker.internal:11434/v1` (по умолчанию
для `LOCAL_LLM_URL`); или поднимите его профилем: `--profile ollama` (`http://ollama:11434/v1`),
`--profile vllm` (`http://vllm:8000/v1`, `LOCAL_LLM_BACKEND=vllm`), `--profile sglang`
(`http://sglang:30000/v1`, `LOCAL_LLM_BACKEND=sglang`); vLLM и SGLang требуют NVIDIA GPU. На ноутбуке M5 32 ГБ разметка одной технологии занимает ~12 с у
`qwen3.6:35b-a3b` и ~40 с у `qwen3.8:27b` — поднимите `RADAR_DEADLINE_SECONDS`.

Тестовый прогон «Новые технологии защиты ИИ-агентов в банках»: 5 минут, 74 источника, 24 кандидата,
все оценены моделью, 15 сигналов в ТОП-15.

### Проверка

```bash
.venv/bin/python -m pytest -q
.venv/bin/ruff check app/radar tests scripts
node --check app/static/radar.js
```

Основные API: `POST /api/searches`, `GET /api/searches/{id}`, `GET /api/searches/{id}/signals`, `GET /api/searches/{id}/rejected`, `GET /api/signals/{id}`, `GET /api/catalog`. Выгрузка: `/api/searches/{id}/export.md` и `.json`. Автоматические тесты используют контролируемые ответы провайдера и не расходуют API-бюджет. Живой прогон проверяется отдельно.

### Проверяемость и ограничения

- Сохраняются прочитанные тексты, URL, даты при наличии, язык, тип, источник оценки доверенности и журнал вызовов моделей.
- Прямые цитаты проверяются на наличие в документе. Это подтверждает происхождение текста, а не истинность заявления автора.
- Оценка 0–100 рассчитывается по фиксированной рубрике и не выдаётся за калиброванную вероятность. Подтверждённая зрелость исключает кандидата.
- Будущие публикации исключаются. При историческом срезе исключаются также материалы с неизвестной датой. Текущая версия страницы не является архивной исторической копией.
- Повторные тексты объединяются консервативно; независимость всех публикаций автоматически не гарантируется.
- Недоступные документы, недостаточное покрытие и прерванные этапы видны пользователю. ТОП может содержать меньше 15 результатов, если доказательств недостаточно.
- Кэш источников хранится в `storage/source_cache`; возраст задаётся `RADAR_CACHE_HOURS`. Кэшированные материалы явно отмечаются.
- По умолчанию стенд привязан к `127.0.0.1`. Для общего доступа настройте контроль доступа на reverse proxy или уровне сети.
- OCR не входит в облегчённый Docker-образ. При необходимости установите `requirements-ocr.txt` отдельно. Текстовые HTML/PDF обрабатываются основным контуром.

## Исходное приложение исследовательских гипотез

**IDEA — Intelligent Discovery & Evaluation Assistant** — локальный MVP интерпретируемой ИИ-платформы для генерации, обоснования и ранжирования научно-исследовательских гипотез.

Система принимает KPI проекта и базу знаний: публикации, патенты, отчеты, результаты экспериментов и технологические документы. IDEA извлекает сущности, строит динамический граф знаний, генерирует проверяемые гипотезы и ранжирует их по новизне, риску, реализуемости и потенциальному эффекту.

## Возможности

- загрузка PDF, DOCX, XLSX, CSV, TXT, MD, PNG/JPG;
- мультиязычный разбор источников и OCR;
- динамический интерактивный граф знаний;
- генерация гипотез через OpenRouter;
- web research со ссылками на статьи, патенты и кейсы;
- экономический контур и план проверки/внедрения;
- feedback, чат, статусы, версии;
- экспорт CSV, Markdown и PDF.

## Запуск

```bash
cp .env.example .env
```

Добавьте ключ в `.env`:

```env
OPENROUTER_API_KEY=...
```

Запустите приложение:

```bash
docker compose up --build
```

Откройте в браузере:

```text
http://localhost:8080
```

Без `OPENROUTER_API_KEY` можно загружать и разбирать документы, но генерация гипотез, чат и web research работать не будут.

## Данные

- `storage/` хранит SQLite-базу, загруженные файлы и OCR-модели.
- `data/` можно использовать как локальную папку с демо-источниками; она монтируется в контейнер как `/app/data`.
